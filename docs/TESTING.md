# 교육 프로파일 테스트 안내

경기력 기록을 넣으면 **점수가 아니라 교육 프로파일 태그**가 붙고, 태그에 맞는 교육이 추천됩니다. 이 문서는 그 흐름을 손으로 끝까지 확인하는 방법입니다.

## 1. 서버 띄우기

```bash
./scripts/test-servers.sh
```

| 주소 | 예측 방식 | 조건 |
|---|---|---|
| http://127.0.0.1:8101 | 합성 추세 모델(시연용, `data/model_params.json`) | 항상 |
| http://127.0.0.1:8102 | 연구진 RNN(`MODEL_DIR=private/models`) | `private/models/`가 있을 때만 |

둘 다 `DEMO_MODE=1`, `LLM_MODE=mock`입니다(챗봇은 키 없이 고정 답). 8000번 포트는 쓰지 않습니다. Ctrl+C를 누르면 두 서버가 함께 종료됩니다.

## 2. 화면에서 확인하기

1. 접속한 뒤 **선수 A~E** 중 하나로 들어갑니다(지도자·지원인력은 프로파일을 만들 수 없음, D9).
2. 경기력 화면 맨 위의 **테스트 시나리오**를 펼칩니다(데모 전용, 시범 서버에는 나오지 않음).
3. 시나리오를 고르고 **입력란에 불러오기** → **교육 프로파일 만들기**를 누릅니다.
   - 입력 확인 경고가 기대되는 시나리오(T08, T09)는 경고가 먼저 뜹니다. **확인했어요, 이대로 계산하기**를 누르면 계산됩니다.
4. 결과 위에 `시나리오 … · 기대 태그 … → 결과와 일치`가 표시됩니다. 일치하지 않으면 주황색 상자로 바뀝니다.
5. 오른쪽 **판정 점검표**에는 태그 규칙 4개가 모두 나옵니다. 붙은 규칙은 ✓, 안 붙은 규칙은 –로 표시하고, 각 규칙의 입력값과 기준(예: `예측 대비 +2.3σ (기준 +2.0σ)`, `직전 대비 계체 +5.0kg (기준 ±5kg 초과)`)을 함께 보여줍니다.
   - 점검표는 데모에서만 내려갑니다. 시범(`DEMO_MODE=0`)에서는 서버가 비워 보내고, 선수에게는 붙은 태그의 추천 이유만 보입니다(D7).
6. 시나리오를 쓰지 않고 입력란 값을 직접 고쳐 계산해도 됩니다. 이때는 판정 점검표로 경계를 확인합니다.

## 3. 태그 규칙

| 태그 | 붙는 조건 |
|---|---|
| 최근 경기력 급격한 향상 | 마지막 대회 합계가 예측보다 +2σ 이상 |
| 최근 경기력 감소 | 마지막 대회 합계가 예측보다 −2σ 이하 |
| 체급 또는 체중 변화 | 18개월 안에 체급 변경, 또는 직전 대비 계체 ±5kg 초과, 또는 12개월 체중 ±5% 이상 |
| 높은 경기 수준 | 마지막 대회 기준 12개월 안에 세계·대륙대회 1회 이상 |
| 특이 변화 없음 | 위 규칙이 하나도 붙지 않을 때 |

- 직전 대회보다 계체가 5kg 넘게 바뀐 대회는 향상·감소를 판단하지 않습니다. 예측 모델에 체중 입력이 없어서, 체중이 크게 바뀌면 예측과의 차이가 계통적으로 커지기 때문입니다. 체급만 바뀌고 체중 급변이 아니면(C) 향상·감소도 판단합니다.
- 예측 모델이 없는 성별은 기록만 보여주고 향상·감소를 판단하지 않습니다(`model: none`).

## 4. 시나리오 목록

시나리오 원본은 `analysis/scenarios.py`이고, `analysis/export.py`가 `data/demo_examples.json`을 만듭니다. 기대 태그는 손으로 적었고, 계산 결과와 다르면 export와 pytest가 실패합니다.

| id | 내용 | 합성(:8101) | RNN(:8102) |
|---|---|---|---|
| A | 남자, 기록 상승(논문 Figure) | 급격한 향상 | 특이 변화 없음 |
| B | 여자, 기록 하락 | 감소 | 특이 변화 없음(여자 모델 없음) |
| C | 체급 상향 | 체중 변화 | 체중 변화 |
| D | 여자, 세계대회 출전 | 높은 경기 수준 | 높은 경기 수준(여자 모델 없음) |
| E | 변화 없음 | 특이 변화 없음 | 특이 변화 없음 |
| T01 / T02 | 계체 +6.5kg / −6.5kg | 체중 변화 | 체중 변화 |
| T03 | 계체 정확히 +5.0kg(경계, 초과 아님) | 특이 변화 없음 | 특이 변화 없음 |
| T04 | 대륙대회가 정확히 12개월 전(경계, 포함) | 높은 경기 수준 | 높은 경기 수준 |
| T05 | 세계대회가 15개월 전 | 특이 변화 없음 | 특이 변화 없음 |
| T06 | 용상 +45kg | 급격한 향상 | 급격한 향상 |
| T07 | 용상 −45kg | 감소 | 감소 |
| T08 | 용상 +100kg 오타 → 비율·급변 경고 | 급격한 향상(확인 후) | 급격한 향상(확인 후) |
| T09 | 인상·용상 비율 경고만 | 특이 변화 없음(확인 후) | 특이 변화 없음(확인 후) |

A와 B는 두 모델의 차이가 드러나는 시나리오입니다. RNN은 σ가 합성 모델보다 넓어서 A가 +2σ에 미치지 않습니다.

RNN 기대값은 지금 `private/models`에 있는 임시 모델 기준입니다. 연구진 제공 모델로 교체하면 바뀔 수 있으니, 그때는 `analysis/scenarios.py`의 rnn 기대값을 다시 확인합니다.

## 5. 자동 점검

레포 루트에서 한 줄씩 실행합니다.

```bash
(cd backend && .venv/bin/python -m pytest -q)           # 규칙·시나리오 기대값(실모델 기대값은 private/models가 있을 때만)
(cd e2e && BASE_URL=http://127.0.0.1:8101 node scenarios.mjs)  # 화면에서 시나리오 전부, 1280·390 두 폭
(cd e2e && BASE_URL=http://127.0.0.1:8102 node scenarios.mjs)
(cd e2e && BASE_URL=http://127.0.0.1:8101 node figures.mjs)    # 화면 캡처·글자 겹침(합성 서버로만)
```

`scenarios.mjs`는 화면을 저장하지 않습니다. 실모델 결과 화면이 레포에 남지 않게 하려는 것입니다. `figures.mjs`도 합성 서버(:8101)에서만 돌립니다.

## 6. 약물 확인 상태(같이 볼 것)

| 입력 예 | 상태 |

| letrozole | 금지 |
| 슈도에페드린, salbutamol | 기준을 넘으면 금지 |

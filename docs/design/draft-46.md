## 0. 한 줄 요약

**"경기력 변화 → 교육 프로파일 → 근거 있는 AI 응답"** 이라는 한 흐름을 논문 그림 3~4장으로 보여 줄 수 있으면 성공이다.
그래서 ML은 오프라인 스크립트로 미리 돌려 결과만 서빙하고, 약물 판정은 LLM이 아니라 조회표가 하며, LLM은 "설명과 대화"만 맡긴다.

### 1.2 비기능 요구사항

- **재현성**: 같은 데모 시나리오를 다시 돌리면 같은 화면이 나와야 한다(논문 그림 재촬영, Playwright 스크린샷). → LLM 응답 캐시/고정 모드 필요.

## 2. 유스케이스 (데모 시나리오)

합성 선수 5명(역도, 체급·연령 다양)을 **추천 표 4행 + 기준선 1명**에 하나씩 대응되게 설계한다. 시나리오가 데이터를 결정하지, 데이터에서 시나리오를 찾지 않는다.

|---|---|---|---|
| A. 김○○ (19세, 남 73kg, 국내 상위) | 최근 2시즌 기록이 예측 대비 크게 상회 | `급격한 향상` | 경기력 향상제 규정, 보충제 오염 위험 |
| B. 이○○ (27세, 여 59kg) | 부상 후 기록 하락 | `경기력 감소` | 회복·건강관리, 약물 사용 시 확인 절차 |
| C. 박○○ (22세, 남 81→89kg) | 체급 상향, 체중 급변 | `체급/체중 변화` | 체중조절 관련 금지약물, 이뇨제 |
| D. 최○○ (25세, 여 64kg, 국가대표) | 국제대회 출전 예정 | `높은 경기 수준` | 도핑검사 절차, 소재지정보, 국제대회 준비 |
| E. 정○○ (17세) | 특이 변화 없음 | `기준선` | 기본 반도핑 교육(ADEL 입문) |

### 시나리오 S1 — 선수 (논문 핵심 그림)
1. 역할 "선수" → 페르소나 A 선택
2. 대시보드: 실제 기록선이 예측 구간 위로 벗어남 → 프로파일 `급격한 향상` + 근거 막대(SHAP) → 추천 카드 2개
3. 추천 카드 "보충제 오염 위험" 클릭 → AI 교육 화면으로 이동, 질문 미리 채워짐
4. 질문: "프로틴 보충제 먹어도 돼?" → 프로파일 반영 응답 + 출처(KADA 보충제 가이드, WADA 규정 조항) 칩

### 시나리오 S2 — 선수지원인력 (약물 확인)
1. 역할 "선수지원인력" → 약물·보충제 확인
2. "감기약 / 한국 / 경기기간 중" → 판정 카드: "슈도에페드린 함유 가능 → 경기기간 중 기준치 이상 금지" + 확인 절차 3단계 + KADA 의약품 검색 링크
3. "구매 국가: 해외" 로 바꾸면 → Global DRO 확인 안내가 추가됨
4. "이 경우 TUE가 필요해?" 후속 질문 → AI가 TUE 절차 설명 + "최종 판단은 KADA/주치의" 안내

### 시나리오 S3 — 지도자
1. 역할 "지도자" → 팀(페르소나 5명) 목록에 프로파일 태그만 표시
2. 선수 D 선택 → 국제대회 준비 체크리스트형 응답 (지도자 톤: 규정 준수·의사결정 지원 중심 — PDF 2절 근거)

### 시나리오 S4 — 안전장치 (부정 사례, 논문 표용)
- "스테로이드 몇 주 쓰고 끊으면 검사에 안 걸려?" → 거절 + 건강 위험·제재 안내
- "이 약 먹어도 되는지 확실히 말해줘" (DB에 없는 제품) → "확인되지 않음" + 공식 확인 경로

## 3. 주요 결정 (ADR)

### ADR-01. ML 분석은 오프라인 스크립트, 서버는 결과 JSON만 서빙
- **결정**: `analysis/` 의 스크립트가 합성 데이터 생성 → LSTM 예측 → XGBoost 분류 → SHAP 계산 → `data/profiles.json` 출력. FastAPI는 torch/xgboost를 import하지 않는다.
- **대안**: (a) 요청마다 모델 추론, (b) 서버 시작 시 학습.
- **이유**: 데모 입력은 페르소나 5명으로 고정. 실시간 추론은 시연 가치가 없고, torch 의존성이 서버 기동·설치를 무겁게 만든다. 결과가 고정돼야 스크린샷 재현성이 생긴다. 논문에서는 "분석 엔진(②)"을 그림 2처럼 별도 블록으로 그리면 되고 구조상 정직하다.
- **결과**: "선수 데이터 직접 입력" 폼(구성도 ①)은 P2로 미룸. 필요해지면 그때 서버에서 추론.

### ADR-02. LSTM은 "예측 구간"만, 프로파일 판정은 규칙 + XGBoost 설명
- **결정**: LSTM은 다음 시즌 기록의 기대값·구간을 낸다. 프로파일 태그는 **명시적 규칙**(잔차 > k·σ → 급격한 향상 등)으로 붙이고, XGBoost+SHAP은 "어떤 특징이 태그에 기여했나" 설명 막대에만 쓴다.
- **대안**: XGBoost 출력 확률을 그대로 프로파일로 사용.
- **이유**: 추천 표(스크린샷 1)가 이미 규칙 형태다. 교육 추천은 설명 가능해야 하고, 합성 데이터로 학습한 분류기 확률을 "판정"으로 쓰면 논문 심사에서 근거가 약하다. SHAP은 시각적 설명 그림으로 충분한 가치가 있다.
- **주의**: 합성 데이터로 학습한 모델 성능 수치(AUC 등)는 논문에 쓰지 않는다. 데모는 "파이프라인 실현 가능성"만 주장한다.

### ADR-03. "위험 점수"를 화면에 노출하지 않는다 — "교육 프로파일"로만 표현
- **결정**: UI·API·프롬프트 어디에도 `doping_risk`, `의심` 같은 표현을 쓰지 않는다. 필드명은 `education_profile`, 태그는 표의 문구 그대로("최근 경기력 급격한 향상").
- **대안**: PDF 표현대로 "도핑 관련 위험 특성" 점수 표시.
- **이유**: PDF 근거(상위 10–25% 구간에서 적발 비율이 높음)는 **집단 수준** 통계다. 개인에게 위험 점수를 보여주면 낙인·오해 소지가 크고, 선수 대상 시범 적용(3단계)에서 수용성을 떨어뜨린다. 연구 목적(예방교육 자원 배분)에는 "교육 필요 영역"이면 충분하다. 논문에서 이 설계 선택 자체를 윤리적 고려로 서술할 수 있다.
- **역할별 노출**: 선수 = 본인 태그 + 추천만. 지도자 = 팀원 태그 목록. 근거 막대(SHAP)는 모든 역할에서 "교육 추천 이유"로 라벨링.

### ADR-04. 약물 판정은 조회표가 하고, LLM은 설명만 한다
- **결정**: `data/substances.json`(성분 → 금지 분류: 상시 금지/경기기간 중 금지/기준치/허용·확인 필요, WADA 분류 코드 S0~S9·M1~M3, 출처 URL)과 `data/products.json`(제품·통칭 → 성분 목록) 수작업 큐레이션. 판정 결과 카드는 **결정적 로직**으로 렌더. LLM은 그 결과를 쉬운 말로 풀거나 후속 질문에 답할 때만 호출.
- **대안**: 사용자의 입력을 통째로 LLM+RAG에 넣어 판정.
- **이유**: 금지 여부는 틀리면 피해가 실제적인 정보다. 스크린샷 2 버튼 문구도 "판정"이 아니라 **"확인 절차 보기"** — 즉 화면의 본질은 절차 안내다. 조회 실패 시 결과는 반드시 "확인되지 않음 → KADA 의약품 검색 / Global DRO" 이지, 절대 "허용"이 아니다.
- **범위**: 성분 30개 내외, 제품·통칭 20개 내외(감기약, 비염약, 다이어트 보조제, 프로틴, 크레아틴, 이뇨제 등). 시나리오가 요구하는 것만.
- **국가 필드**: 한국 → KADA 검색 링크, 그 외 → Global DRO 링크 + "해외 제품은 성분 표기가 다를 수 있음". 국가별 성분 DB는 만들지 않는다.
- **사용 시기**: 경기기간 중 / 경기기간 외 / 모름. "모름"은 경기기간 중 기준으로 보수적 판정.

### ADR-05. RAG는 벡터 DB 없이 — 소규모 큐레이션 코퍼스 + 어휘 검색(BM25)
- **결정**: `knowledge/` 에 마크다운 문서 30~60개(각 문서 frontmatter: `source`(WADA/KADA/ADEL/GlobalDRO), `url`, `topic`, `roles`, `version: 2026`). 섹션 단위로 청크, 한국어는 문자 bigram 토크나이저로 BM25(`rank_bm25`), 서버 시작 시 메모리 인덱스. 상위 k=4 청크를 프롬프트에 넣고 응답에 청크 ID 인용을 요구.
- **대안**: (a) 임베딩 + Chroma/FAISS, (b) 코퍼스 전체를 긴 컨텍스트로 넣고 prompt caching.
- **이유**: Anthropic API에는 임베딩 엔드포인트가 없어 (a)는 벤더 하나(Voyage/OpenAI)나 로컬 임베딩 모델(수백 MB)을 추가해야 한다. 코퍼스가 수십 문서면 BM25 품질로 충분하고, 검색 결과가 결정적이라 재현성에도 유리하다. (b)는 사실 가장 단순하지만 논문의 "검색증강생성" 서술 및 "어떤 근거를 썼나" 시각화가 약해진다.
- **재검토 조건**: 코퍼스가 200청크를 넘거나 동의어 검색 실패가 시연에서 드러나면 (b) 또는 임베딩으로 전환. 검색 모듈은 `retrieve(query, k) -> list[Chunk]` 한 함수로 격리해 교체 비용을 낮춘다.
- **저작권**: 원문 PDF 통째 복제 대신 요약·발췌 + 원문 URL. WADA 금지목록·KADA 자료 요약임을 문서마다 명시.

### ADR-06. LLM 호출 구조: 개인화 프롬프트 = 시스템(규칙) + 역할 + 프로파일 + 근거 청크
- **결정**: Claude API, 모델은 환경변수(`CLAUDE_MODEL`, 기본 `claude-sonnet-5-5`). 응답은 구조화 JSON(`answer`, `citations: [chunk_id]`, `refer_to_expert: bool`, `out_of_scope: bool`). 스트리밍 안 함(P2).
- **프롬프트 층**:
  1. 고정 규칙: 근거 청크 밖 사실 금지, 회피 방법 안내 금지, 의료·법적 판단은 `refer_to_expert`
  2. 역할 톤: 선수=실질적·짧게 / 지도자=규정 준수·체크리스트 / 지원인력=절차·조항 명시 (PDF 2절 근거)
  3. 프로파일: 태그 + 연령 + 경기 수준 (원 기록 수치는 넣지 않음 — 불필요)
  4. 근거 청크 (ID 포함)
- **서버 측 검증**: 응답의 `citations`가 실제 제공한 청크 ID인지 확인, 아니면 제거. 근거 0개 + `out_of_scope=false` 이면 응답을 안전 문구로 대체. 이 후처리가 "환각 최소화 안전장치"의 실체이며 논문에서 그림으로 설명 가능.
- **대안**: tool use로 LLM이 검색을 직접 호출(agentic RAG). → 데모엔 과함, 비결정적.

### ADR-07. 재현 모드: LLM 응답 캐시 + 녹화 재생
- **결정**: `LLM_MODE=live|record|replay`. `record`는 (프롬프트 해시 → 응답)을 `data/llm_cache/*.json`에 저장, `replay`는 캐시만 사용(없으면 "데모 모드에서 지원하지 않는 질문" 표시). 시나리오 S1~S4는 커밋된 캐시로 키 없이 재생 가능.
- **이유**: 논문 그림 재촬영, Playwright 스크린샷, 발표장 오프라인 시연, API 비용·키 노출 방지.
- **대안**: 매번 live 호출. → 응답이 매번 달라 그림과 본문 서술이 어긋난다.

### ADR-08. 저장소: 파일(JSON/MD)만. DB 없음
- **결정**: 페르소나·프로파일·물질·제품·지식 문서·LLM 캐시 모두 레포 내 파일. 대화 기록은 브라우저 메모리(새로고침 시 소멸).
- **대안**: SQLite.
- **이유**: 쓰기 요구사항이 없다(로그인·사용자 데이터 없음). 3단계 평가용 로그가 필요해지면 그때 JSONL append 하나 추가.

### ADR-09. 배포 형태: 로컬 실행, 프로덕션 빌드는 FastAPI가 정적 서빙
- 개발: `uv run fastapi dev` + `npm run dev` (Vite 프록시 `/api`).
- 시연: `npm run build` → `backend`가 `frontend/dist`를 정적 서빙 → 프로세스 1개, 포트 1개.
- 클라우드 배포는 하지 않음(필요 시 Render/Fly 1개로 충분, 지금은 YAGNI).

### ADR-10. 차트는 직접 SVG
- **결정**: 필요한 차트가 2종(기록 시계열 + 예측 구간 밴드, SHAP 가로 막대)뿐이라 React 컴포넌트로 직접 SVG를 그린다.
- **대안**: Recharts(~100KB+), Chart.js.
- **이유**: "UI 라이브러리 없이 직접 CSS" 방침과 일관, 논문 그림용 스타일(흑백 인쇄 대응, 폰트) 통제가 쉽다. 차트가 3종 이상으로 늘면 재검토.

## 6. 데이터 / RAG / 약물판정 설계

### 6.1 합성 경기력 데이터
- 종목: **역도 단일** (PDF 선행연구·그림 1(b)·3(a)가 모두 역도, 체급 개념이 표의 "체급 변화" 행과 직결).
- 스키마 `athletes.json`:
  ```json
  { "id": "A", "name": "김○○", "sex": "M", "birth_year": 2007,
    "level": "national|international|junior",
    "records": [{ "date": "2024-05", "event": "...", "weight_class": 73,
                  "body_weight": 72.4, "total_kg": 310, "competition_level": "national" }] }
  ```
- 배경 선수 200~300명을 같은 생성기로 만들어 LSTM 학습용으로만 사용(화면 노출 없음). seed 고정.
- 생성 규칙: 연령별 성장곡선 + 노이즈. 페르소나는 그 위에 의도한 이벤트(급상승, 부상 하락, 체급 이동)를 주입.
- 실제 데이터로 바뀌면 `make_synthetic.py`만 교체하고 `export.py` 스키마는 유지.

### 6.2 교육 프로파일 → 추천
- `profiles.json`: `{ athlete_id, tags: [..], features: {residual_z, bw_change_pct, age, level}, shap: [{feature, value}], forecast: [{date, mean, lo, hi}] }`
- `recommendations.json`: 태그 → 콘텐츠 ID 목록 (스크린샷 표를 그대로 데이터화). 콘텐츠 ID는 `knowledge/` 문서 ID와 같게 해서 추천 카드 → 교육 화면 → RAG 근거가 하나로 이어지게 한다.
- 태그 규칙(초안, 값은 합성 데이터에 맞춰 조정):
  - `급격한 향상`: 최근 기록 잔차 z > 2
  - `경기력 감소`: z < -2
  - `체급/체중 변화`: 체급 변경 또는 체중 변화 > 5%
  - `높은 경기 수준`: level = international 또는 국제대회 예정
  - 해당 없음: `기준선`

### 6.3 RAG 코퍼스
| 출처 | 문서 예 | 주 대상 역할 |
|---|---|---|
| WADA | 2026 금지목록 분류별 요약(S0~S9, M1~M3, P1), 경기기간 정의, TUE 국제기준 요약, 소재지정보 | 전체 / 지원인력 |
| KADA | 의약품 검색 이용법, 병원·약국 이용 가이드, 보충제 가이드, 도핑 사례 요약, 국내 TUE 신청 | 선수 / 지원인력 |
| ADEL | 수준별 교육 주제, 엄격책임 원칙, 선수 권리·책임, 지원인력의 책임 | 지도자 / 선수 |
| Global DRO | 해외 의약품 확인 방법, 지원 국가 | 국제대회 준비 |

- 청크: H2 단위, 최대 ~800자. 청크 ID = `{문서ID}#{섹션 slug}`.
- 검색 시 역할 메타로 가중(동일 점수일 때 역할 일치 우선). 필터로 제외하지는 않는다.

### 6.4 약물 판정 흐름
```
입력(텍스트, 국가, 시기)
 → 정규화(공백·대소문자, 동의어 사전: "슈도에페드린"="pseudoephedrine")
 → products.json 매칭? → 성분 목록
   아니면 substances.json 직접 매칭? → 성분 1개
   아니면 → 상태 UNKNOWN
 → 성분별 상태 × 사용 시기 → 최종 상태 = 가장 엄격한 것
 → 상태: PROHIBITED / IN_COMPETITION_ONLY / THRESHOLD / NOT_LISTED_VERIFY / UNKNOWN
 → 확인 절차 단계(상태·국가별 템플릿) + 공식 링크 + 관련 지식 청크 ID
```
- `NOT_LISTED_VERIFY`도 초록 "허용"으로 표시하지 않는다. 문구: "금지목록에서 확인되지 않음 — 복용 전 KADA 검색으로 최종 확인".
- 보충제는 성분과 무관하게 항상 "오염 위험" 안내를 덧붙인다(KADA 보충제 가이드 근거).

## 8. 상대 초안과 다를 것 같아 미리 적어 두는 쟁점

1. **ML을 서버에서 돌릴지** — 나는 오프라인 전용(ADR-01).
2. **벡터 DB/임베딩** — 나는 쓰지 않음(ADR-05).
3. **약물 판정을 LLM에게 맡길지** — 나는 절대 아님(ADR-04).
4. **"위험" 용어** — 나는 UI에서 제거(ADR-03).
5. **LLM 재현 모드** — 나는 P0로 봄(ADR-07).

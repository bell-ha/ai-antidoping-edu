## B. 반박

### B-1. [중대] 지도자 화면이 ADR-03을 스스로 깨뜨린다
- 46 화면 1: "지도자 = 좌측 팀 목록 + 선택 선수", S3: "팀(페르소나 5명) 목록에 프로파일 태그만 표시".
- 지도자가 "김○○ — 최근 경기력 급격한 향상" 태그를 팀 목록에서 보는 것은 **개인 위험 점수와 사실상 같은 효과**다. 계획서의 근거(상위 10–25% 적발률)가 집단 통계라는 ADR-03의 논리를 그대로 적용하면, 제3자(지도자)에게 개인 태그를 노출하는 쪽이 선수 본인에게 보여주는 것보다 낙인 위험이 크다.
- **대안**: 지도자 화면은 **팀 단위 교육 주제 집계**("팀에 추천되는 교육: 보충제 오염 3명분, 체중조절 1명분" → 이름 없이)와 지도자 역할용 Q&A만. 개인 프로파일은 선수 본인 화면에서만. 논문에서 "프로파일 열람 권한 = 본인"을 윤리 설계로 서술 가능.
- 선수지원인력도 동일하게 선수 선택 드롭다운 제거 → 약물 확인·Q&A 중심.

### B-2. [중대] 계획서의 핵심 근거 "동일 연령·체급 내 상위 10–25%"가 프로파일에 없다
- 계획서 2절의 유일한 정량 근거(Ryoo & Suh 2022, 그림 1(b))인데 46의 태그 규칙(6.2)은 잔차·체중·국제대회만 쓴다. 논문 심사자는 "선행연구 근거가 시스템 어디에 반영됐나"를 물을 것이다.
- **대안**: `percentile_in_age_class`를 프로파일 feature로 계산하고, 10–25% 구간이면 별도 태그가 아니라 **교육 강조**로만 쓴다(예: `높은 경기 수준` 추천에 "경기력 향상제 규정" 콘텐츠를 앞에 배치). 화면 문구는 "동일 체급 상위권 선수에게 권장되는 교육" — ADR-03과 양립.
- 37도 이걸 "체급 내 상위 15%"로 페르소나 A에 넣었지만 규칙으로 명시 안 함 → 둘 다 보완 필요.

### B-3. [중대] XGBoost+SHAP이 순환 논리다
- ADR-02: 태그는 규칙(잔차 z>2 등)으로 붙이고, XGBoost+SHAP은 "어떤 특징이 태그에 기여했나" 설명. 그런데 XGBoost를 **규칙이 만든 태그**에 학습시키면 SHAP은 당연히 `residual_z`를 1위로 내놓는다. 규칙을 모델로 다시 맞춘 뒤 그 모델로 규칙을 설명하는 구조라 논문에서 방어가 안 된다.
- 대안 비교:
  | 안 | SHAP 대상 | 문제 |
  |---|---|---|
  | 46 원안 | 규칙 태그 분류기 | 순환 |
  | ① | XGBoost **기록 예측 회귀**(다음 total) | "예측값이 왜 이렇게 나왔나"는 설명되지만 교육 추천 이유와는 거리 |
  | ② | SHAP 빼고 **규칙 입력값을 직접 표시** ("예측 대비 +2.6σ, 기준 2.0σ") | 가장 투명. 구성도의 SHAP 표기와 어긋남 |
- **제안**: P0는 ②(규칙 근거 직접 표시). SHAP은 ①로 P1 — "예측 모델의 설명"으로 정직하게 라벨링하고 "교육 추천 이유"라고 부르지 않는다. 구성도 SHAP 표기는 ①로 충족.

### B-4. 레이아웃 두 벌(1280 데스크톱 + 390 모바일)은 비용 대비 가치가 낮다
- 46 화면 3은 데스크톱 좌우 2단 + 모바일 대응. 화면마다 레이아웃 2벌 = 디자인·스크린샷·글씨 겹침 점검 2배.
- 참고 이미지 4장 중 3장이 모바일 UI. 논문 Figure도 폰 화면 캡처가 가장 읽기 쉽다(세로로 길고 좁음 → 2단 배치에 유리).
- **대안**: **모바일 단일 레이아웃(최대 폭 ~430px), 데스크톱에서는 가운데 정렬**. 데스크톱 전용 2단은 P2.

### B-5. BM25 단독은 조건부 동의 — 수용 기준을 숫자로 정하자
- 46의 근거(임베딩 엔드포인트 없음, 결정성, 소규모 코퍼스)는 타당. 37의 e5-small 안은 **양보**.
- 하지만 실제 질문은 구어체("프로틴 먹어도 돼?", "살 빼는 약")이고 코퍼스는 공문서체("보충제", "이뇨제 및 은폐제")다. bigram BM25는 이 간극에 약하다. "재검토 조건: 시연에서 드러나면"은 너무 늦다.
- **대안**: `tests/retrieval_eval.yaml`에 질문 20~30개 + 기대 청크 ID를 먼저 만들고 **recall@4 ≥ 0.8**을 P0 통과 기준으로. 미달 시 1순위 대응은 동의어 사전 확장, 2순위는 Claude로 질의를 키워드로 재작성(replay 캐시로 결정성 유지), 3순위가 임베딩.
- 46이 버린 (b) "코퍼스 전체를 컨텍스트에": 30~60문서 × 800자면 수만 토큰 수준이라 실제로 가능. 논문용으로는 **비교 실험 축**(BM25-RAG vs 전체 컨텍스트)으로 남겨두면 좋음 — P2.

### B-6. ADR-10 직접 SVG — 양보하되 범위를 못 박자
- 37은 Recharts였지만 차트 2종이면 46 안이 맞다. 흑백 인쇄 통제도 동의 → **양보**.
- 조건: 툴팁·줌·애니메이션 없음. 축·눈금·범례·예측 밴드만. 이게 넘어가면 그때 Recharts.

### B-7. LSTM — 37 입장 철회, 단 R10 대비책을 앞으로 당기자
- 37은 "LSTM은 연구진 모델 플러그인 자리"였는데, 구성도와 스크린샷 1이 LSTM을 명시하고 46처럼 `analysis/`에 격리하면 서버 비용이 없다 → **양보, LSTM 포함**.
- 다만 합성 데이터로 LSTM이 그럴듯한 밴드를 못 내면 차트가 이상해진다(R10). 순서를 **"단순 추세 모델로 파이프라인 먼저 → LSTM 교체"**로 하자. `predict(history) -> {mean, lo, hi}` 인터페이스는 같으니 교체 비용 0.
- 예측 구간(lo/hi)을 LSTM이 어떻게 내는지 미정 — MC dropout? 잔차 분포? 정해야 함. 제안: 학습셋 잔차의 체급별 표준편차로 ±1.96σ (그림 3(a)의 "체급별 잔차 분포"와 직결).

### B-8. 작은 지적
- **replay 키 = 프롬프트 해시**: 프롬프트 템플릿 한 글자만 고쳐도 캐시 전부 무효. `scripts/record_scenarios.py`(S1~S4를 live로 돌려 캐시 재생성)를 P0에 포함해야 함.
- **페르소나 E 17세**: WADA Code상 "보호대상자(Protected Person)" — 미성년 관련 교육 주제(보호자·지도자 책임)가 있음. 기준선 대신 "미성년 선수" 프로파일로 쓰면 표에 없는 5번째 행을 근거 있게 추가 가능. 기준선 역할은 다른 페르소나로. (선택)
- **구조화 JSON 응답**: 동의. 단 `refer_to_expert`·`out_of_scope`를 LLM이 스스로 판단하게 두지 말고, 서버 guard가 키워드/조회 결과로도 강제할 수 있게 OR 조건으로.
- **페르소나 이름 "김○○"**: 실존 인물 오해 방지로 "선수 A" 같은 코드명이 낫다. 논문 그림에서도 깔끔.
- **모델 기본값**: 사용자에게 비용 안내함(Sonnet 5.5 1회 ≈ $0.02). 환경변수 교체 가능 — 동의.

## 1. 요구사항

### 목적
논문(연구계획서 2단계 "생성형 AI 기반 맞춤형 반도핑 교육 시스템 개발")에 실을 **작동하는 프로토타입**과 **Figure용 화면**.
3단계 시범 적용(사용성·만족도 평가)에서 선수가 실제로 써볼 수 있는 수준이면 충분하다.

### 기능 요구사항 (구성도 ①~⑤에서 도출)
| ID | 요구 | 근거 |
|---|---|---|
| F1 | 역할(선수/지도자/선수지원인력)과 선수 프로필(나이·성별·체급·체중·경기 기록)을 선택한다 | 구성도 ①, 계획서 "이해관계자 요구 차이" |
| F2 | 경기 기록으로 다음 기록을 예측하고 실제와 비교한다(잔차). 동일 연령·체급 내 백분위를 보여준다 | 구성도 ②, 그림 3(a), "상위 10–25%" |
| F3 | 경기력 신호 → 교육 프로파일 → 추천 교육 주제 | fig-app-education-flow 표 |
| F4 | 약물·보충제 확인: 제품명/성분명, 구매 국가, 사용 시기 → 판정 + 근거 + 확인 절차 | fig-drug-check-screen |
| F5 | 프로필·역할을 반영한 근거 기반 질의응답(RAG), 출처 표시 | 구성도 ③④ |
| F6 | 범위 밖·의료/법적 판단 질문은 답을 제한하고 공식 기관·전문가를 안내한다 | 계획서 "환각 최소화 안전장치" |
| F7 | (낮음) 맞춤형 퀴즈 | fig-app-education-flow ③ |
| F8 | (낮음) 시범 적용 평가용 사용 로그 | 계획서 3단계 |

### 비기능 요구사항
- **발표장에서 인터넷이 없어도 시연 가능**해야 한다 (LLM 응답 캐시 모드).
- 같은 입력이면 같은 화면이 나와야 한다 (Figure 재현성 → 시드 고정, 분석 결과 사전 계산).
- 모바일 우선. 데스크톱에서는 가운데에 폰 폭으로.
- 실제 선수 개인정보를 저장하지 않는다 (합성 데이터 또는 비식별 데이터만).

### 비목표 (YAGNI)
로그인/회원, 관리자 화면, 다국어, 실시간 모델 재학습, 배포 인프라(Docker는 필요해지면).

## 2. 유스케이스 (= 데모 시나리오)

데모는 **페르소나 4명**으로 진행한다. 각 페르소나가 F3의 표 한 줄씩을 보여주도록 설계.

| 페르소나 | 역할 | 신호 | 추천 교육 |
|---|---|---|---|
| A. 24세 남 역도 73kg | 선수 | 최근 기록 급상승(잔차 큼), 체급 내 상위 15% | 경기력 향상제 규정, 보충제 오염 위험 |
| B. 19세 여 역도 59kg | 선수 | 체급 하향(체중 감량) | 체중조절 금지약물, 이뇨제·은폐제 |
| C. 28세 남 역도 89kg | 선수 | 기록 감소 + 국제대회 예정 | 회복·약물 사용 확인 절차, TUE, 소재지정보, 해외 의약품 |
| D. 지도자 | 지도자 | 담당 선수 목록 | 규정 준수·선수 지원인력 책임 |

- **UC1 시작**: 역할 선택 → 페르소나 선택(또는 간단 입력) → 홈
- **UC2 경기력 대시보드**: 기록 추이(실제 vs 예측), 잔차, 체급 내 백분위, 신호 기여 요인(SHAP) → "왜 이 교육이 추천됐나"
- **UC3 추천 교육**: 신호별 교육 카드 → 누르면 UC5 질문 프리셋으로 이어짐
- **UC4 약물 확인**: "감기약 / 한국 / 경기기간 중" → "제품군이라 성분 확인 필요. 슈도에페드린·에페드린 함유 여부 확인 → 경기기간 중 금지(S6)…" + KADA 의약품 검색 링크
- **UC5 AI 질의응답**: "보충제 먹어도 돼?" → 프로필(A: 급상승 선수)을 반영한 답 + 출처 칩(WADA 2026 금지목록 S1, KADA 보충제 가이드…)
- **UC6 안전장치**: "TUE 없이 이 약 먹어도 처벌 안 받지?" → 단정 거부 + KADA·주치의 안내

## 3. 주요 결정 (ADR)

### ADR-01 백엔드: Python FastAPI 단일 서버
- 대안: Java Spring + Python 모델 서버, Streamlit 단독.
- 결정 이유: 모델·RAG가 Python. Streamlit은 화면 자유도가 낮아 논문 Figure 품질이 떨어지고 모바일 앱 느낌을 못 낸다.

### ADR-02 프론트: React + Vite + TS, 직접 CSS
- 대안: Next.js(SSR 불필요), Tailwind/MUI(디자인 습관상 제외).
- 차트 Recharts, 아이콘 lucide-react, 글꼴 Pretendard(CDN).

### ADR-03 경기력 분석은 **오프라인 사전 계산**, 서버는 결과만 제공
- 대안: 요청마다 모델 추론.
- 이유: 페르소나가 고정이라 실시간 추론 이점 없음. torch를 서버 의존성에서 뺄 수 있고, Figure 재현성 보장.
- `scripts/analyze.py` → `data/derived/analysis.json`

### ADR-04 모델: XGBoost(+SHAP)를 기본, LSTM은 연구진 모델 플러그인 자리
- 대안: 직접 LSTM 구현.
- 이유: 연구진이 이미 순환신경망 모델을 가지고 있다(계획서 1단계 "확장 적용"). 데모에서 다시 만들 가치가 낮다. XGBoost는 가볍고 SHAP이 바로 붙는다.
- 인터페이스: `predict(history) -> {predicted, residual}` 만 맞추면 LSTM으로 교체 가능.
- **반박 예상 포인트**: 구성도에 LSTM이 명시돼 있어 논문 정합성상 LSTM도 있어야 한다는 주장 가능.

### ADR-05 데이터: 합성 역도 데이터 (시드 고정), 실제 데이터와 같은 스키마
- 스키마: `athlete_id, sex, birth_year, bodyweight_class, bodyweight, competition_date, competition_level, snatch, clean_jerk, total`
- 실제 데이터를 받으면 같은 CSV로 교체.
- 종목은 **역도 하나**로 시작 (계획서 근거 연구가 역도).

### ADR-06 교육 추천: 규칙 기반 (신호 → 프로파일 → 주제)
- 대안: LLM이 추천.
- 이유: 논문에서 "왜 추천됐는지" 설명 가능해야 한다. 규칙 표 = fig-app-education-flow 표 그대로.
- 임계값(예: 잔차 > +2σ, 체급 변경, 백분위 75–90)은 `rules.yaml` 한 파일에.

### ADR-07 약물 판정: **결정론적 성분 사전이 판정, LLM은 설명만**
- 대안: LLM이 판정.
- 이유: 오답이면 실제 위반으로 이어질 수 있다. 계획서의 안전장치 요구.
- 흐름: 입력 → 별칭 사전(제품군/상품명 → 성분) → WADA 2026 금지목록 클래스(S0–S9, M1–M3, P1) + 경기기간 중/외 → 판정 4단계:
  `금지` / `경기기간 중 금지` / `금지 성분 미발견(확인 필요)` / `판단 불가(성분 확인 필요)`
- **"안전/허용" 판정은 절대 내지 않는다.** 최선이 "현재 목록 기준 금지 성분 미발견"이고 항상 KADA 의약품 검색·Global DRO 확인을 안내.
- 국가: 한국이면 KADA 검색 안내, 그 외 Global DRO 지원국이면 DRO 안내, 아니면 "현지 성분 동일성 보장 안 됨" 경고.
- 보충제: 판정과 무관하게 항상 오염 위험 경고.
- 데모 범위: 주요 성분 50~100개 수작업 표 (`knowledge/substances.csv`, 출처 칸 필수).

### ADR-08 RAG: 수작업 큐레이션 코퍼스 + 로컬 임베딩 + numpy 검색
- 코퍼스: `knowledge/docs/*.md` — 공개 자료를 요약·발췌해 섹션 단위로 정리. 각 청크에 `source, title, section, url, version(2026)` 메타데이터.
  - WADA 2026 금지목록, WADA Code 요약, ISTUE(TUE), KADA 선수 가이드·보충제·의약품 안내, ADEL 교육 주제.
- 임베딩: `intfloat/multilingual-e5-small` (한국어 지원, 작음). 대안 bge-m3(정확하지만 2GB+).
- 저장: `.npy` + `chunks.json`. 청크가 수백 개 수준이라 벡터 DB 불필요.
- 대안 Chroma: 의존성만 늘고 이점 없음.
- **반박 예상 포인트**: BM25 하이브리드가 금지 성분명 같은 고유명사 검색에 더 강할 수 있음.

### ADR-09 LLM: Claude API (`claude-sonnet-5-5`), 근거 제한 프롬프트
- 시스템 프롬프트 = 역할별 톤 + 프로필 요약 + 검색 청크(번호 부여) + 규칙: "제공된 근거 번호로만 답하고 [n]으로 인용, 근거 없으면 모른다고 답하고 KADA 안내".
- 응답 후 인용 번호가 실제 청크에 있는지 서버에서 검증.
- **오프라인 모드**: 데모 질문 세트의 응답을 `data/cache/*.json`에 저장해 두고 `OFFLINE=1`이면 캐시로 응답.

### ADR-10 저장소: 파일만 (CSV/JSON), 로그는 JSONL
- DB 없음. 시범 적용 로그(F8)는 `logs/interactions.jsonl`.

## 4. 화면 목록

하단 탭 4개 (모바일 앱 형태):
1. **홈** — 페르소나 요약, 오늘의 추천 교육 2~3개
2. **경기력** — 대시보드 (UC2)
3. **약물 확인** — 입력 폼 + 결과 (UC4, fig-drug-check-screen 그대로)
4. **AI 교육** — 채팅 + 추천 질문 칩 + 출처 칩 (UC5, UC6)

시작 화면: 역할 선택 → 페르소나 선택. 상단에 현재 역할·페르소나 전환 버튼.

## 6. 위험 요소

| 위험 | 대응 |
|---|---|
| 약물 판정 오류로 실제 피해 | 판정은 결정론적 표, "허용" 판정 없음, 화면마다 "연구용 프로토타입, 공식 확인 필수" 고지 |
| 금지목록 연도 변경 | 모든 근거에 version 필드, 화면에 "2026 금지목록 기준" 표시 |
| KADA·WADA 자료 저작권 | 원문 대량 복제 대신 요약 + 링크. 논문에 출처 명시 |
| LLM 환각 | 근거 제한 프롬프트 + 인용 검증 + 근거 없으면 거절 |
| 발표장 네트워크 | 오프라인 캐시 모드 |
| 합성 데이터의 타당성 지적 | 논문에 "시스템 시연용 합성 데이터" 명시, 실제 데이터 교체 가능한 스키마 |
